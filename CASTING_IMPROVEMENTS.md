# Предложения по улучшению кастинга и обходу лимита спикеров в Dub Studio

Этот документ подготовлен для обсуждения архитектурных доработок программы в новой сессии программирования. В нем описаны текущие ограничения, способы быстрой настройки окружения и план рефакторинга для перехода на **лице-центричный кастинг**.

---

## 1. Текущая проблема: Лимит в 4 персонажа

При обработке видео с большим количеством актеров (более 4) система кастинга не создает карточки для всех персонажей, даже если лица успешно детектируются на видео.

### Почему это происходит:
1. **Ограничение Sortformer**: Базовая модель диаризации (`diar_streaming_sortformer_4spk-v2.onnx`) аппаратно ограничена распознаванием **максимум 4 спикеров**.
2. **Зависимость кастинга от диаризации**: Текущая архитектура является **спикеро-центричной** (Speaker-centric). Бэкенд сначала находит спикеров по звуку, а затем ищет под них лица. Если диаризатор выдал только 4 спикера, то и лиц будет привязано не более 4. Все остальные обнаруженные лица отбрасываются.
3. **Сброс голосовой переразметки (Re-diarization)**: В проекте есть алгоритм переразметки по голосу через **WeSpeaker** (иерархическая кластеризация AHC), способный обходить лимит в 4 голоса. Однако, если кластеризатор находит $\le 4$ спикеров (из-за слишком мягкого порога слияния), он отменяет переразметку и откатывается к базовому результату Sortformer.

---

## 2. Быстрое решение: Настройка переменных окружения

До переписывания кода можно существенно улучшить распознавание большего числа спикеров, настроив переменные окружения бэкенда:

1. **Проверить модель WeSpeaker**:
   Убедиться, что файл `models/faces/wespeaker/voxceleb_resnet34_LM.onnx` существует. Без него переразметка по голосу полностью отключается.
2. **Повысить порог разделения голосов (`DUB_VOICE_CLUSTER_COS`)**:
   По умолчанию порог равен `0.42`. Если поднять его до **`0.48 - 0.55`** (например, `0.50`), алгоритм AHC станет более чутко реагировать на разницу в голосах и перестанет объединять разных актеров в одну группу. Это позволит выделить более 4 спикеров и запустить переразметку.
3. **Увеличить лимит персонажей (`DUB_VOICE_MAX_CHARS`)**:
   По умолчанию стоит предохранитель в `8` персонажей. Для видео с большим кастом установите `DUB_VOICE_MAX_CHARS=12` или `15`.

## 3. Предложение по доработке: Лице-центричный кастинг (Decoupled Casting)

Для полной стабильности необходимо отвязать (декоплировать) детекцию персонажей от диаризации аудио, перейдя к **лице-центричной модели** (Face-centric).

### Сравнение подходов:

```
[Текущий спикеро-центричный подход]
Аудио -> Диаризация (макс 4) -> Поиск лиц под спикеров -> Вывод макс 4 карточек

[Предлагаемый лице-центричный подход]
Видео -> Поиск и кластеризация лиц (всего N человек) -> Вывод N карточек персонажей
                                                                |
Аудио -> Диаризация ------------------------------------> Мягкое связывание (Лицо <-> Голос)
                                                                |
                                                          Ручная корректировка связей в UI
```

### Детали реализации:

1. **Детекция и кластеризация лиц на видео**:
   * Функция `cluster_faces` запускается независимо от таймлайна аудио. Она находит все повторяющиеся лица в видеофайле и группирует их в визуальные кластеры (например, находит 8 уникальных людей).
   * Выбирается медоид (самый четкий аватар) для каждого лица.
2. **Создание карточек персонажей**:
   * Карточки в `casting.json` создаются на основе **визуальных кластеров**, а не спикеров. Пользователь в интерфейсе увидит карточки всех 8 человек.
3. **Алгоритм со-встречаемости (Мягкое связывание)**:
   * Система пытается автоматически связать каждый визуальный кластер с голосовым спикером по принципу пересечения таймлайнов (лицо в кадре + голос на аудио).
   * Если лицо появляется на экране, но не говорит (или диаризатор его не выделил), персонаж все равно выводится в UI, но его голос временно остается в статусе "Не назначен/Закадровый".
4. **Интерфейс ручного кастинга**:
   * Добавить в UI возможность для пользователя вручную переназначить голос/актера озвучки для любого визуального персонажа. Это компенсирует любые ошибки автоматической диаризации.
5. **Параметры фильтрации лиц**:
   * Ввести фильтрацию случайных лиц (массовки) по минимальному времени присутствия в кадре (например, отсекать лица, мелькавшие суммарно менее 3 секунд).
   * Добавить в настройки проекта параметр `DUB_FACES_MAX_COUNT` для ограничения вывода карточек (например, брать только "Top 8" самых часто показываемых лиц).

## 4. Предложения по доработке UI (Вкладка «Транскрипт»)

Для удобного управления кастингом непосредственно во время редактирования проекта предлагается внести следующие изменения в интерфейс вкладки **«Транскрипт»**:

1. **Кнопка ручного запуска кастинга**:
   * Рядом с кнопками запуска распознавания/анализа добавить кнопку **«Запустить кастинг»** (или «Пересчитать кастинг»).
   * Это позволит пользователю в любой момент обновить или пересчитать файл `casting.json` (например, после изменения порогов или переключения режимов) без полного перезапуска фазы анализа всего проекта (что занимает много времени из-за ASR и Gemma).
2. **Переключатель режима кастинга (dropdown / toggle)**:
   * Рядом с кнопкой запуска разместить выбор режима:
     * **Спикеро-центричный (по голосам)** — классический режим с привязкой к таймлайнам аудио-диаризации (лимит до 4 спикеров по умолчанию).
     * **Лице-центричный (по лицам)** — новый режим независимого поиска лиц на видео (с поддержкой ручного распределения голосов).
3. **Раздельные поля лимитов Спикеров и Лиц (с режимом «Авто»)**:
   * Разместить рядом с переключателем режима два независимых поля ввода (с возможностью оставить их пустыми или выбрать значение **«Авто»** по умолчанию):
     * **Поле «Макс. спикеров» (Max Speakers)**:
       * **Режим «Авто»**: Алгоритм диаризации и AHC-кластеризации голосов определяет количество спикеров автоматически по установленным порогам сходства (`DUB_VOICE_CLUSTER_COS`).
       * **Жесткое ограничение (число)**: Запускается алгоритм слияния (merge smallest into nearest) самых мелких кластеров с наиболее близкими крупными, пока количество голосов не приравняется точно к указанной цифре.
     * **Поле «Макс. лиц» (Max Faces)**:
       * **Режим «Авто»**: Визуальная кластеризация лиц автоматически группирует все обнаруженные лица по порогу схожести.
       * **Жесткое ограничение (число)**: Система ранжирует найденные лица по частоте появления на экране и оставляет ровно `N` (например, `6`) наиболее частых персонажей, отбрасывая фоновые лица (массовку).
4. **Ожидаемый флоу**:
   * Пользователь может настроить кастинг гибко: например, оставить «Макс. спикеров» в режиме **«Авто»**, но жестко задать «Макс. лиц» равным `6`, чтобы на экране гарантированно отобразились 6 ключевых персонажей. Бэкенд перестраивает `casting.json` в соответствии с выбранной комбинацией настроек при нажатии кнопки запуска.

## 5. Стратегия безопасного тестирования (Изоляция изменений)

Для предотвращения сбоев в работе стабильной версии программы предлагается следующая стратегия внедрения:

1. **Изоляция на панели редактирования**:
   * Все новые контроли (кнопка пересчета, выбор режима, поля ввода лимитов) размещаются **только во вкладке «Транскрипт»** в редакторе открытого проекта.
2. **Главный экран без изменений**:
   * Основной экран импорта видео и первоначального запуска анализа проекта (`api.analyze(...)`) остается без изменений и работает в стандартном автоматическом режиме. Это гарантирует, что базовый импорт не сломается при наличии багов в новых алгоритмах.
3. **Финальная интеграция**:
   * Перенос настроек кастинга на главный экран импорта (как опции для первоначального анализа) будет осуществлен только после завершения ручного тестирования и калибровки порогов распознавания.
